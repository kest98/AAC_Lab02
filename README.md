В моём эксперименте Release оказался быстрее Debug примерно в 10 раз.

Что я обнаружил при сравнении IL

При сравнении IL-кода в ILSpy я увидел следующие отличия:
В Debug-версии метода Add() присутствуют инструкции nop, которых нет в Release.
В Release компилятор убрал промежуточные операции с локальными переменными: в Debug есть stloc и ldloc, а в Release они отсутствуют.
Количество IL-инструкций в методе Add() изменилось с 10 до 4.


Ответы на контрольные вопросы
1. IL  — это промежуточный язык. Если бы C# сразу компилировался в машинный код, то программа работала бы только на процессорах одного типа . А благодаря IL, мы компилируем код в него, и он работает везде.

2. Потому что внутри .dll лежит не машинный код, а тот самый IL-код. IL — вполне читаемая структура. Поэтому программа ILSpy легко читает этот файл и переводит его обратно в понятный C# код.

3. В версии Debug кода больше. Там есть пустые операции nop , а также лишние шаги: компилятор сохраняет промежуточный результат в переменную, а потом достает его оттуда. В версии Release компилятор всё это выкинул, и код стал коротким.

4. Потому что у них разные задачи. Debug нужен для поиска ошибок, поэтому компилятор не трогает код, оставляет все промежуточные шаги и кучу отладочной информации. А Release нужен для того, чтобы программа работала быстро.

5. Потому что строки хранятся внутри .dll файла в открытом виде, компилятор их никак не шифрует. Если открыть .dll в HEX-редакторе или декомпилировать через ILSpy, эти строки можно легко найти и прочитать.
